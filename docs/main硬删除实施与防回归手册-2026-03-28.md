# main 硬删除实施与防回归手册（2026-03-28）

## 1. 目标与结论

目标：彻底删除系统内对 `main` 作为默认 agent 的依赖，不再存在“隐式主角色”概念。  
结论：可做，但必须一次性收敛默认值策略、数据迁移策略和测试门禁，否则会出现“main 被 runtime 复活”与“状态错桶”回归。

本手册用于指导实现阶段，避免遗漏关键点。

---

## 2. 风险总览（必须先统一再改）

### P0 风险（不处理会直接回归）

1. 前端删掉 `main` 后，主进程仍有 `|| 'main'` 回退，导致 `main` 被重新写回事件链路。
2. 仅移除默认值但不统一解析器，voice/chat 无显式 agentId 时会落空值，导致 office/value/persona 链路错乱。
3. valueState 与 shortTermMemory 未迁移旧 `main` 数据，用户会感知“人格/数值断档”。

### P1 风险（功能可运行但行为错误）

1. `activeAgentId` 历史语义中 `''` 等价 `main`，若不迁移会选错 active agent。
2. desktopBridge web fallback store 仍使用主角色 fallback，导致空态与切换逻辑异常。
3. 测试只覆盖 `main` 路径，非 `main` 实际行为失真。

---

## 3. 影响面与必改清单

> 原则：禁止散落写 `|| 'main'`；必须通过统一解析函数决定 runtime agent。

### 3.1 前端（Renderer）

关键位置：

- `front_end/src/components/office/officeSceneConfig.js`
  - `OFFICE_PRIMARY_AGENT_ID` 与 `normalizeOfficeState/buildOfficeDisplayState` 不可再强制构造 `main`。
- `front_end/src/App.jsx`
  - `resolvedConversationAgentId` 回退链末端不能回退 `main`。
  - `activeAgentId` 与本地 `agentRoleConfig` 同步不再把 `main` 编码为 `''`。
  - `handleRemoveOfficeAgent` 去掉“primary 不可删”语义，改为“active 删除后的回退策略”。
  - immersive/valueState 默认跟踪逻辑不能依赖 `main`。
- `front_end/src/services/desktopBridge.js`
  - `normalizeSettingsResponse/normalizeOfficePresenceRequest/mergeWebOfficeAgents` 去除主角色 fallback。
  - office web fallback store 改为“空态可接受 + 首次 presence 自动设 active”。
- `front_end/src/components/config/AgentRoleSettingsPanel.jsx`
  - 去掉对 `main` 的过滤和禁用规则。

### 3.2 主进程（Electron）

关键位置：

- `desktop/electron/services/chat/conversationRuntime.js`
  - `DEFAULT_AGENT_ID = 'main'` 需要改为无默认（`null`）并由统一解析器提供 agentId。
- `desktop/electron/main.js`
  - `normalizeMainAgentId(...) || 'main'` 类逻辑统一替换。
  - chat/system -> office/value/persona 事件桥接处禁止直接注入 `'main'`。
- `desktop/electron/services/settingsStore.js`
  - `DEFAULT_OPENCLAW_SETTINGS.agentId` 不再默认为 `main`。
  - legacy flat `agentId` 的兼容读写需迁移定义。
- `desktop/electron/services/valueState/valueStateStore.js`
  - `DEFAULT_AGENT_ID='main'` 需移除；空 agent 时行为需明确定义（拒绝或 UNSCOPED）。
- `desktop/electron/services/valueState/valueProposalService.js`
  - 多处 `payload.agentId || ... || 'main'` 必须替换为统一解析逻辑。
- `desktop/electron/services/persona/shortTermMemoryStore.js`
  - key/path fallback 不能再默认 `main`。

## 4. 实施策略（按顺序执行，避免半完成态）

### 阶段 A：先建“统一 agent 解析器”

在主进程建立单点解析逻辑（示例语义）：

`request.agentId > options.agentId > office.activeAgentId > firstAvailableAgentId > null`

要求：

1. 任何 runtime 写入事件（chat/voice/value/persona/office）都必须经过此解析器。
2. 解析结果为 `null` 时，返回结构化错误（如 `agent_required`）或进入只读 idle，禁止悄悄补默认值。
3. 全仓禁止新增字面量 `'main'` 作为 fallback（资源命名和历史文档示例除外）。

### 阶段 B：迁移存储语义

1. `agentRoleConfig` 迁移：
   - 历史 `activeAgentId=''` 不再解释为 main，改为“未设置 active”。
2. `settings` 迁移：
   - `openclaw.agentId='main'` 转为空或映射到用户现存首 agent（按最终产品规则定）。
3. value/memory 迁移：
   - 提供一次性迁移，把 `main` 数据映射到目标 agent（需要映射规则与回滚备份）。

### 阶段 C：前端/配置面板去主角色化

1. Agent 配置界面显示并管理全部 agent，不再保留内置主角色。
2. office 空态允许 `agents=[]` 与 `activeAgentId=''`。
3. 删除 active agent 后，统一回退到首个可用 agent；若无可用 agent 则保持空态。

### 阶段 D：测试矩阵与门禁

将核心用例参数化为至少两组：`main`（legacy）与 `agent-alpha`（新路径），并补空态与 invalid 场景。

## 5. 防回归测试矩阵（必须执行）

### 5.1 参数维度

1. `agentId`: `undefined` / `''` / `main` / `agent-alpha` / `invalid`
2. `backend`: `nanobot` / `codex` / `openclaw(legacy)`
3. `transport`: `stdio` / `http` / `ws`（fixtures）
4. `office state`: 空 agents / 单 agent / 多 agent / active 被删除

### 5.2 关键断言

1. 全链路事件（submit -> delta -> done/error）中的 `agentId/backend/routeKey` 一致。
2. 不出现隐式回退到 `main`。
3. valueState 与 shortTermMemory 的读写键一致，不出现新旧桶分裂。
4. 空态下系统行为明确（错误可见或 idle），不崩溃、不 silent fail。

### 5.3 执行命令门禁

1. `pnpm run test:desktop`
2. `pnpm run test:frontend`
3. `cd front_end && pnpm run lint`
4. `pnpm run test:regression:phase3-real-device`（至少一轮）

## 6. 上线验收标准（全部满足才可合并）

1. 代码中不再存在作为默认回退的 `|| 'main'`（白名单仅限资源名与历史兼容映射层）。
2. 所有受影响测试通过，新增参数化用例覆盖非 `main` 主路径。
3. 真实运行中未显式传 agentId 时，系统行为符合新规则（明确报错或明确空态）。
4. 数据迁移后，历史用户的 value/memory 不丢失（抽样验证迁移前后等价）。
5. 文档契约更新完毕，不再把 `main` 当作唯一示例。

---

## 7. 推荐的回滚预案

1. 保留 `legacyMainAlias` 开关（仅短期）：
   - 开启时将旧 `main` 请求映射到新策略的 active agent。
   - 关闭时严格执行无默认 agent 规则。
2. 迁移脚本执行前做数据快照备份。
3. 若线上出现 agent 解析空值高频错误，可临时启用 alias 开关止损，再修复调用侧。

---

## 8. 实施备注

1. 这是高风险改造，不建议拆成过长周期分支；建议按阶段 A/B/C/D 连续落地并一次性回归。
2. 如需“平滑过渡”，可先发布兼容版（保留 alias + 新测试），再发布严格版（移除 alias）。
