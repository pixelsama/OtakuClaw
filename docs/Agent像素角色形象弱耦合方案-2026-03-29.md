# Agent 像素角色形象弱耦合方案（2026-03-29）

## 1. 背景与目标

当前 Pixel Room 的角色精灵由全局 Pixel Pack 资产键和硬编码映射驱动。Agent 角色配置已经支持 `avatar.live2d/static`，但尚未具备 Pixel Room 专用的“像素角色档案选择”能力。

本方案目标：

1. 在 Agent 角色配置中新增 Pixel Room 专用角色选择能力。
2. 保持与 Pixel Pack 的资源契约联动，以支持未来“坐下/靠家具锚点”等联动效果。
3. 避免将 Pixel Room 角色配置与 Live2D/静态立绘渲染模式混为同一层概念。
4. 保证旧配置与旧资源包向后兼容。

## 2. 现状链路（以当前代码为准）

### 2.1 角色配置链路

1. Agent 角色配置当前持久化在前端 `localStorage(openclaw.agentRoleConfig.v1)`，由 `front_end/src/App.jsx` 读写。
2. 配置会通过 `desktopBridge.office.publishPresence(...)` 同步到 `office-state`。
3. `resolveOfficeSceneState(...)` 基于 `officeState.agents[]` 生成 occupants，并在 `OfficeScene` 中渲染。

### 2.2 像素资源链路

1. `pixel pack` 负责资产导入/激活与协议 URL（`openclaw-pixel-pack://`）。
2. 渲染侧使用 `buildOfficeSceneAssetRegistry(OFFICE_SCENE_ASSET_REGISTRY, pixelPackState)` 合并内置资产与 pack 资产。
3. `resolveOfficeOccupantSprite(...)` 当前主 Agent 走硬编码状态映射，Guest Agent 走 hash 选图（`guestAnim1-6/guestRole1-6`），并不读取 Agent 自定义像素角色字段。

### 2.3 关键约束

1. `normalizeOfficeAgent(...)` 是显式白名单摘字段，当前未保留 `pixelRoom`，会在归一化时丢失。
2. `front_end/src/App.jsx` 中 `normalizeStoredAgentRole(...)` 也是白名单风格，需要同步保留 `pixelRoom`。
3. `derivePrimaryOfficeAgent(...)` 当前构造 primary agent 时未透传 `pixelRoom`，需要补齐参数透传路径。

## 3. 目标架构

分层如下：

- `Pixel Pack`：资源与角色档案定义层（assets + characters）。
- `Agent 配置`：角色选择层（只选择 `characterId`，可带少量覆盖）。
- `OfficeScene`：渲染解析层（按 `agent.pixelRoom.characterId + businessState` 查 profile，再回退硬编码）。

设计原则：

1. `pixelRoom` 不放在 `avatar` 下。
2. `avatar` 继续只负责 Live2D/静态立绘。
3. Pixel Room 角色配置是“场景层配置”，不是“主舞台渲染模式”。

## 4. 数据契约变更

## 4.1 Pixel Pack Manifest（向后兼容新增）

在现有 manifest 上新增可选字段 `characters`：

```json
{
  "schemaVersion": 1,
  "packId": "star-office",
  "version": "2.0.0",
  "assets": {
    "starIdle": { "path": "sprites/star-idle.png", "type": "spritesheet", "cols": 8, "rows": 6 },
    "starWorking": { "path": "sprites/star-working.png", "type": "spritesheet", "cols": 8, "rows": 5 },
    "errorBug": { "path": "sprites/error-bug.png", "type": "spritesheet", "cols": 10, "rows": 11 }
  },
  "characters": {
    "star": {
      "label": "Star",
      "stateSprites": {
        "idle": { "assetKey": "starIdle" },
        "writing": { "assetKey": "starWorking" },
        "researching": { "assetKey": "starWorking" },
        "executing": { "assetKey": "starWorking" },
        "syncing": { "assetKey": "starWorking" },
        "error": { "assetKey": "errorBug" }
      },
      "anchors": {
        "stand": { "offsetY": 0 },
        "sit": { "offsetY": -8 }
      }
    }
  }
}
```

说明：

1. `characters` 为可选；缺失时走旧逻辑。
2. `stateSprites.<state>.assetKey` 必须引用 `assets` 中存在的 key。
3. `anchors` 首版可透传存储，渲染层先不强制消费（为 Phase 4 家具联动预留）。

## 4.2 Agent Role Config（不放在 avatar 下）

在每个 agent 对象新增可选 `pixelRoom`：

```json
{
  "agentId": "primary",
  "displayName": "Star",
  "avatar": {
    "renderMode": "live2d",
    "live2d": {},
    "static": {}
  },
  "pixelRoom": {
    "characterId": "star",
    "overrides": {}
  }
}
```

说明：

1. `pixelRoom.characterId` 仅表达“该 Agent 在 Pixel Room 使用哪个角色档案”。
2. `overrides` 预留给后续按状态覆写精灵（首版可为空对象）。

## 4.3 归一化与存储链路要求

1. `front_end/src/App.jsx` 的 agent normalize/store 流程必须保留 `pixelRoom`。
2. `front_end/src/components/office/officeSceneConfig.js` 的 `normalizeOfficeAgent(...)` 必须保留 `pixelRoom`，避免字段在 office-state 往返时丢失。
3. `desktop/electron/services/officeStateStore.js` 已按“保留未知字段”风格合并对象，原则上无需破坏式改动。

## 5. 渲染解析规则

目标行为（替代纯硬编码）：

1. 读取 `occupant.pixelRoom.characterId`。
2. 先从 active pixel pack manifest 的 `characters[characterId]` 查 profile。
3. 若未命中，则从内置 `BUILTIN_CHARACTER_PROFILES` 查 profile。
4. 用 `businessState` 查 `stateSprites[state]`，未命中回退 `stateSprites.idle`。
5. 若 profile 缺失、assetKey 缺失或资产不存在，回退当前 legacy 逻辑（主 Agent 硬编码 + Guest hash）。

这样可确保：

1. 新 pack + 新 agent 配置可走新链路。
2. 旧 pack 或旧配置仍稳定可渲染。
3. Guest Agent 与 Primary Agent 都可按 `characterId` 独立配置形象。

## 6. 分阶段落地

### Phase 1：契约与校验

1. 扩展 pixel pack manifest 校验，支持 `characters`。
2. 校验 `stateSprites.*.assetKey` 对 `assets` 的引用有效性。
3. 保持 `schemaVersion: 1` 不变（新增可选段，不破坏旧包）。
4. 同步扩展字段保留链路：`normalizeOfficeAgent(...)`、`normalizeStoredAgentRole(...)` 增加 `pixelRoom` 白名单透传。
5. `derivePrimaryOfficeAgent(...)` 增加 `pixelRoom` 透传参数，调用方从 active agent config 传入。

### Phase 2：Agent 配置面板

1. Agent Role 面板新增 Pixel Room 角色选择区。
2. 候选项来自“当前激活 pack 的 `characters` 列表”。
3. 保存到 agent 的 `pixelRoom.characterId`。

### Phase 3：渲染接线

1. 新增 `BUILTIN_CHARACTER_PROFILES`（建议放在 `officeSceneConfig.js`），作为无 pack 时的默认角色档案来源。
2. `resolveOfficeOccupantSprite(...)` 同时支持 Primary/Guest 的 `characterId` 解析。
3. 解析优先级固定为：`active pack characters > BUILTIN_CHARACTER_PROFILES > legacy`。
4. 保持现有 `businessState -> 场景区位` 逻辑不变。

### Phase 4（后续）：家具联动

1. 消费 `anchors.sit/stand`。
2. 在 furniture 规则中加入“可坐家具锚点”解析。
3. 增加 `sit` 姿态资源约定与状态切换策略。

## 7. 回归测试建议

1. 无 pack / 旧 pack / 新 pack 三种场景渲染回归。
2. Agent 切换 `characterId` 后，Pixel Room occupant 形象正确变化。
3. `office-state` 往返后 `pixelRoom` 字段不丢失。
4. Primary 与 Guest 均验证 `characterId` 生效，Guest 缺失时回退 hash 逻辑。
5. `businessState=syncing/error` 显示符合映射与回退预期。
6. 旧 `avatar.renderMode`（Live2D/静态立绘）行为不受影响。

## 8. 结论

该方案实现了“资源契约与角色选择解耦但不脱钩”：

1. Pixel Pack 继续拥有资源与场景联动能力。
2. Agent 配置获得 Pixel Room 角色选择权。
3. 概念边界清晰：`avatar` 管主舞台，`pixelRoom` 管像素房间。
