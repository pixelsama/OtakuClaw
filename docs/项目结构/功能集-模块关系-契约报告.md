# Free-Agent-Vtuber-Openclaw 功能集结构与契约报告

## 0. 说明
本报告基于并行代码探索整理，目标是回答三件事：
- 每个功能集由哪些模块组成（主进程 / 预加载 / 渲染层）
- 每个功能集与其他功能集如何连接
- 存在什么协议/契约（IPC、事件信封、资源协议、设置结构）

## 2. 分功能集详解

## FS-01 应用内核与桥接总线
### 模块组成
- 主进程
  - `desktop/electron/main.js`
  - 负责：服务实例化、IPC注册、协议注册、窗口与托盘生命周期
- 预加载
  - `desktop/electron/preload.js`
  - 负责：将最小化能力暴露到 `window.desktop`
- 渲染桥接
  - `front_end/src/services/desktopBridge.js`
  - 负责：统一 Electron/Web 双态 API、规范化事件与设置结构

### 与其他功能集联系
- 是所有功能集的接入总线：FS-02~FS-12 都通过它注册或转发
- 负责把主进程事件转成渲染可消费事件（例如 `conversation:event`）

### 协议/契约
- `window.desktop` 暴露分区：`conversation/settings/voice/voiceModels/live2dModels/staticAvatars/capture/captureOverlay/windowMode/windowControls/nanobotRuntime/acpRunnerRuntime/nanobotSkills/pixelPack/appUpdater`
- 主事件总线：`conversation:event`
- 状态事件：`office-state:changed`、`value-state:changed`、`download-task:progress`

  - `front_end/src/hooks/useStreamingChat.js`
  - `front_end/src/hooks/chat/useStreamingSubtitleBridge.js`
  - `front_end/src/components/chat/*`

### 与其他功能集联系
- 调用 FS-06/FS-07（Nanobot 或 ACP 后端）
- 向 FS-09 发送 office/value 相关事件（通过 `main.js` 中 event 映射）
- 与 FS-03 互通：语音 ASR 最终文本会回注到会话流

### 协议/契约
- 请求 IPC
  - `conversation:submit-user-text`
  - `conversation:abort-active`
  - `conversation:permission:resolve`
  - 兼容路径：`chat:stream:start` / `chat:stream:abort`
- 事件信封（统一）
  - `conversation:event`，核心字段：`channel/type/streamId/turnId/agentId/backend/routeKey/sessionId/profileId/timestamp/payload`
- 聊天事件类型（`channel=chat`）
  - `stream-start`、`text-delta`、`segment-ready`、`permission-request`、`done`、`error`
- 并发策略契约
  - `policy=latest-wins` 或 `policy=queue`

## 3. 跨功能集主链路（重点）

## 3.1 语音到聊天闭环
1. 渲染层发送 `voice:session:start` + `voice:audio:chunk` + `voice:input:commit`
2. ASR 输出 `asr-final`
3. `main.js` 在 `onAsrFinal` 调用 `conversationRuntime.submitUserText(...source='voice-asr')`
4. 聊天事件以 `conversation:event(channel=chat)` 回流
5. 分段文本进入 TTS 队列，发出 `tts-chunk`，渲染 ACK (`voice:playback:ack`)

## 3.2 聊天到 Office/Value 状态联动
1. 聊天/系统事件在 `main.js` 被映射为 `office` 或 `value` 更新
2. `officeStateStore` 与 `valueStateStore` 更新后分别广播 `office-state:changed` / `value-state:changed`
3. 渲染层 `OfficeScene` 与 `App.jsx` 订阅并重绘

## 3.3 模型下载到运行时生效
1. `VoiceSettingsPanel` 调 `voice-models:*`
2. `voiceModelLibrary` 触发下载 + python runtime/env 准备（FS-05）
3. 进度通过 `voice-models:download-progress` 和 `download-task:progress`
4. 选择变更触发 voice runtime reload/warmup

## 3.4 资源导入到场景渲染
1. 导入 `Live2D/Avatar/PixelPack` ZIP
2. 主进程库验证与落盘
3. 通过 `openclaw-model/openclaw-avatar/openclaw-pixel-pack` 协议读取资源
4. 渲染层组件按 URL 加载并显示

## 4. 全局契约模式总结

## 4.1 IPC 响应模式
- 大多数请求遵循：
  - 成功：`{ ok: true, ... }`
  - 失败：`{ ok: false, reason }` 或 `{ ok: false, error: { code, message } }`

## 4.2 事件模式
- `conversation:event` 是核心事件总线，统一信封字段
- 状态型通道独立：`office-state:changed`、`value-state:changed`、`download-task:progress`、`app-updater:state`

## 4.3 安全边界模式
- Renderer 只用 preload 暴露能力，不直接执行 shell/python
- 资源协议与 ZIP 导入都做路径约束/遍历防御
- 密钥优先 keytar，失败降级到文件并保留兼容迁移

## 5. 对“功能集划分”的结论
当前项目可稳定按 12 个功能集治理，边界最清晰的切分轴是：
- 交互主线：聊天（FS-02）+ 语音（FS-03）
- 资源与运行时底座：模型下载（FS-04）+ Python（FS-05）
- 后端能力：Nanobot（FS-06）+ ACP（FS-07）
- 视觉与场景：资产系统（FS-08）+ Office/Value（FS-09）
- 桌面能力：截图（FS-10）+ 模式/窗口（FS-11）+ 设置更新（FS-12）

这套划分与现有模块目录、IPC命名、事件信道基本一致，后续做测试矩阵和重构时可直接复用。
