# 灵山胜境 AI 数字人导览系统开发任务切片

版本：v1.0  
日期：2026-05-05  
依据文档：

1. `docs/灵山胜境AI数字人导览系统PRD-2026-05-05.md`
2. `docs/景区导览服务AI数字人赛题适配改造方案-2026-05-04.md`
3. 当前 `OtakuClaw` Electron + React + Nanobot + Live2D + Voice 项目结构

## 1. 文档目的

本文档把灵山胜境 AI 数字人导览系统拆成可执行开发任务。它不是产品说明，也不是答辩材料，而是后续编码、测试、排期和分工的执行清单。

拆分原则：

1. 先地基，后界面：先完成官方资料包导入、知识库和检索，再做游客端页面。
2. 先准确，后炫技：优先保证官方资料问答准确率和来源追溯。
3. 先默认路径，后高级能力：先让评委打开就是“灵山胜境 AI 导游”，再补后台和大屏。
4. 先 P0 闭环，后 P1 打磨：每个里程碑都必须能单独验收。
5. 旧能力不急删代码，但必须从比赛默认路径隐藏。

## 2. 当前项目落点

### 2.1 可复用模块

| 能力 | 当前文件/模块 | 复用方式 |
| --- | --- | --- |
| Electron 主进程和 IPC | `desktop/electron/main.js`、`desktop/electron/ipc/*` | 新增 `scenicGuide` IPC，继续由主进程读写文件和处理可信逻辑 |
| Preload 安全桥 | `desktop/electron/preload.js` | 暴露最小 `scenicGuide` API |
| Renderer 桥接 | `front_end/src/services/desktopBridge.js` | 增加 scenic guide 桥接和 Web fallback |
| 对话编排 | `desktop/electron/services/chat/conversationRuntime.js` | 接入 scenic RAG 上下文、来源和交互日志 |
| Nanobot 后端 | `desktop/electron/services/chat/backends/nanobotBackend.js` | 接入导游 Prompt 和景区上下文 |
| 语音链路 | `desktop/electron/ipc/voiceSession.js`、`front_end/src/hooks/voice/*` | 复用 ASR/TTS，补数字人 speaking 状态和延迟指标 |
| Live2D | `front_end/src/components/live2d/Live2DViewer.jsx` | 改成导游舞台，接入 listening/thinking/speaking/guiding 状态 |
| 截图捕获 | `desktop/electron/ipc/screenshotCapture.js`、`front_end/src/hooks/chat/useScreenCaptureController.js` | 包装为“拍照问导游”入口 |
| 下载/运行时 | `front_end/src/components/download/*`、`desktop/electron/services/python/*` | 隐藏到管理员高级设置 |

### 2.2 需要默认隐藏的旧入口

1. 像素房间、办公室、家具编辑。
2. 桌宠娱乐化入口。
3. 多 Agent 工作空间叙事。
4. 通用聊天/开发助手文案。
5. Nanobot、Python 环境、模型路径等工程调试信息。

### 2.3 原始数据管理约束

官方资料包不应作为源码提交到仓库根目录。开发任务中需要明确：

1. 应用支持管理员选择资料包目录。
2. 程序只读原始文件。
3. 导入后生成结构化缓存、索引和摘要。
4. 原始 Excel/Docx 如需样例，应放在外部数据目录或以 `.gitignore` 排除。

## 4. 任务优先级

| 优先级 | 定义 |
| --- | --- |
| P0 | 比赛必须有，没有就不成立 |
| P1 | 高奖强相关，建议进入主版本 |
| P2 | 锦上添花，有余力再做 |

任务规模：

| 规模 | 参考 |
| --- | --- |
| S | 半天内，可单文件或少量文件完成 |
| M | 1-2 天，涉及一个小模块和测试 |
| L | 3-5 天，跨主进程/前端/测试 |
| XL | 1 周以上，需要拆成子 PR |

## 16. 全局 Definition of Done

任一任务完成必须满足：

1. 有明确用户可见或开发可验证的产出。
2. 不破坏现有安全边界：文件读写在主进程，密钥不进 Renderer。
3. 不把官方原始资料硬编码进源码路径。
4. 新增服务有单元测试或明确无法测试的说明。
5. 前端新增页面在窄屏下不出现明显重叠。
6. 文案围绕灵山胜境导览，不出现旧项目默认叙事。
7. 任务相关文件提交到 git，原始官方资料不误提交。
