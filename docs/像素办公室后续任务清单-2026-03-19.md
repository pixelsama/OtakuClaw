# 像素办公室后续任务清单

日期：2026-03-19
最近更新：2026-03-21

## 当前状态概览

像素办公室已经从“运行时状态预览”推进到了“可独立查看、可编辑、可扩展的 Pixel Room 原型”。

当前版本已经具备：

1. 独立 `Pixel Room` 页面。
2. `Live2D / Pixel Room` 视图切换。
3. 本地 office state 同步链路。
4. 主 Agent 状态驱动的房间映射。
5. 基础家具系统、素材库面板、拖拽编辑与持久化。
6. 部分 `Star-Office-UI` 独立素材迁移与对象化。
7. 基础状态化家具能力，包括显隐、换帧、多图层和简单 spritesheet 动画。
8. `guest_anim_*` 访客动画资源接入与 guest fallback 逻辑。
9. 多 Agent presence 写入层基础接口，包括批量 upsert、active agent 切换与 agent 移除。

## 当前已完成

### 1. 运行时与状态接入

1. 已在主界面接入本地单机版办公室场景。
2. 已建立 `officeStateStore + IPC` 基础结构，为未来多 Agent 预留扩展位。
3. 已完成主 Agent 的基础状态映射：
   - `idle`
   - `writing`
   - `researching`
   - `executing`
   - `syncing`
   - `error`
4. 已接通 `Nanobot` 的工具提示到办公室活动状态链路。
5. 当前已支持以下中间态映射：
   - `read_file` / `list_dir` / `web_search` / `web_fetch` -> `researching`
   - `write_file` / `edit_file` / `exec` / `spawn` -> `executing`
6. 当最终文本开始输出时，办公室会切回 `writing`。
7. 已支持 `Error Preview`，方便调试仅在特定状态出现的对象。

### 2. 页面结构与视觉迁移

1. 已新增独立 `Pixel Room` 页面视图。
2. 已实现 `Live2D / Pixel Room` 切换。
3. 已迁入当前用于功能评估的 `Star-Office-UI` 房间美术资源。
4. 已把 Pixel Room 视觉从占位式面板推进到原项目风格的独立房间页面。

### 3. 家具系统基础能力

1. 已建立数据驱动的家具配置层。
2. 已支持主题切换。
3. 已支持家具显示/隐藏。
4. 已支持滑杆调位置。
5. 已支持场景内直接拖拽家具。
6. 已支持布局持久化。
7. 已支持状态家具标签，避免把状态对象误认为普通常驻家具。
8. 已支持素材库分类浏览和对象启用/移除。
9. 已支持主题默认对象和额外启用对象共同组成当前房间。

### 4. 已对象化的房间元素

当前已接入为可配置对象的元素包括：

1. `desk`
2. `coffee`
3. `sofa`
4. `bug`
5. `poster`
6. `plantLeft`
7. `plantCenter`
8. `plantBedroom`
9. `flowers`
10. `cat`
11. `serverroom`
12. `syncBeacon`

### 5. 状态化对象能力

当前已经落地的状态化能力包括：

1. `visibleWhenStates`
2. `hiddenWhenStates`
3. `layers`
4. `stateVariants`
5. `frameIndex`
6. `animation`

当前已实际使用的状态化对象：

1. `bug`
   - 仅在 `error` 显示。
2. `serverroom`
   - 会根据 `writing / researching / executing / syncing / error` 切换帧。
3. `flowers`
   - 会在 `error` 时切换帧。
4. `cat`
   - 会在 `syncing / error` 时切换帧。
5. `syncBeacon`
   - 仅在 `syncing` 时显示，并播放 spritesheet 动画。
6. `coffee`
   - 已改成多图层对象，带 `coffee shadow`。
7. `sofa`
   - 已改成单对象多图层，`shadow` 不再作为独立可编辑家具暴露。

### 6. 多 Agent 访客表现与写入层基础

1. 已接入 `guest_anim_1..6.webp`。
2. 非主 Agent 现在会优先使用 `guest_anim_*`，并保留 `guest_role_*` 作为 fallback。
3. guest occupant 已支持最小帧动画，不再只是纯静态占位图。
4. `officeStateStore` 已支持：
   - `upsertAgents`
   - `setActiveAgent`
   - `removeAgent`
5. `desktopBridge.office` 已支持：
   - `upsertAgents`
   - `setActiveAgent`
   - `removeAgent`
6. `upsertAgent` 已修正为“只更新该 agent，不再隐式抢占 `activeAgentId`”。

## 当前未完成

### 1. 多 Agent 仍是结构预留

1. 当前数据结构已经支持多 Agent。
2. 但真实接入仍以主 Agent 为主。
3. 真实的 multi-agent producer 还没有接入主进程 store。
4. 当前只是“写入层和渲染层已准备好”，还没有稳定的数据来源负责持续写入 support/guest agents。

### 2. 仍有不少房间内容在背景里

1. 并不是整张房间里的所有元素都已对象化。
2. 目前仍有一部分结构和装饰烘焙在背景图中。
3. 这意味着当前家具系统已经可用，但还不是“全对象化场景系统”。

### 3. 资产系统仍处于最小可用阶段

当前还没有：

1. 搜索
2. 仅显示未加入对象
3. 收藏
4. 回滚
5. 恢复默认布局面板
6. 导入 / 导出
7. 图层排序编辑
8. 更完整的动画编辑面板

### 4. Pet Mode 还没有接入 Pixel Room

1. 当前 Pixel Room 主要是 window 模式页面。
2. `PetShell` 还没有接入像素房间或迷你房间展示。

### 5. 状态协议仍不够通用

1. 当前 `researching / executing` 主要来自 `Nanobot tool-hint`。
2. 还不是完整的、后端无关的通用推理阶段协议。
3. `thinking` 等更细状态仍未系统化接入。

## 下一阶段任务

### 任务 1：接入 `guest_anim_*`，升级多 Agent 访客表现

目标：让未来多 Agent 进入房间时，不再只是静态占位图。

当前状态：已完成。

### 任务 2：定义并接入多 Agent presence 协议

目标：让房间真正消费未来多 Agent 的统一状态源。

建议内容：

1. 定义统一的 `agent presence` 数据结构。
2. 明确字段：`agentId`、`displayName`、`businessState`、`detail`、`role`、`sceneState`、`updatedAt`。
3. 决定多 Agent 写入主进程 store 的归集方式。
4. 为 producer 明确 lifecycle 规则：join、heartbeat、remove、active agent 选举。
5. 设计同一区域多 Agent 占位策略和优先级。

### 任务 3：继续扩充独立可摆放对象

目标：尽可能把原项目里已经独立的素材对象化。

建议内容：

1. 继续盘点 `Star-Office-UI` 当前剩余独立素材。
2. 优先接入那些不需要从背景硬拆的对象。
3. 逐步减少“背景里烘死的内容”。

### 任务 4：继续做完整资产系统

目标：把当前最小编辑器升级为真正可用的资产系统。

建议内容：

1. 搜索。
2. “仅显示未加入对象”。
3. 收藏。
4. 恢复默认布局。
5. 回滚上一次配置。
6. 导入 / 导出布局和主题。
7. 图层顺序与层级编辑。

### 任务 5：继续升级状态化与动画系统

目标：让房间对象不只是“会显示/隐藏”，而是具备更完整的状态表现能力。

建议内容：

1. 把动画配置继续标准化。
2. 支持更丰富的多图层状态变体。
3. 支持更完整的状态切换表现。
4. 评估是否要让部分对象支持可配置动作面板，而不是只在配置文件里写死。

### 任务 6：Pet Mode 办公室接入

目标：让桌宠模式也能看到简化版像素房间或房间状态缩略视图。

建议内容：

1. 在 `front_end/src/shells/PetShell.jsx` 接入轻量版办公室组件。
2. 控制尺寸、信息密度和鼠标交互，避免破坏现有 pet mode 体验。
3. 明确桌宠模式下的展示策略：完整房间、迷你房间，或仅角色状态区。

## 推荐优先级

1. 定义并接入多 Agent presence 协议
2. 继续扩充独立可摆放对象
3. 完整资产系统
4. 升级状态化与动画系统
5. `pet mode` 接入 Pixel Room

## 建议的阶段验收点

1. 先确认当前 Pixel Room 的房间对象数量和编辑体验是否已经达到“可持续扩展”的标准。
2. 再确认 `serverroom / cat / flowers / syncBeacon` 这些状态对象的表现是否符合预期。
3. 再确认 `guest_anim_*` 的访客动画观感是否已经达到“可接受的多 Agent 占位表现”。
4. 之后进入真正的 multi-agent producer，不要先急着做复杂资产系统 UI。
5. 等多 Agent 表现稳定后，再做完整收藏、回滚、导入导出能力。

## 备注

当前版本已经不是单纯的“办公室预览”，而是一个正在形成中的像素房间系统。

后续开发建议保持这个顺序：

1. 先把多 Agent 和访客表现做对。
2. 再继续扩对象和状态化能力。
3. 最后把资产系统和编辑系统做完整。

这样能避免先把编辑器做得很重，但底层对象模型和多 Agent 展示还不稳定的问题。
