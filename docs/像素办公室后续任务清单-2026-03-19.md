# 像素办公室后续任务清单

日期：2026-03-19

## 当前已完成

1. 已在主界面接入本地单机版办公室场景。
2. 已建立 `officeStateStore + IPC` 基础结构，为未来多 Agent 预留扩展位。
3. 已完成主 Agent 的基础状态映射：`idle`、`writing`、`syncing`、`error`。
4. 已接通 `Nanobot` 的工具提示到办公室活动状态链路。
5. 已支持以下中间态映射：
   - `read_file` / `list_dir` / `web_search` / `web_fetch` -> `researching`
   - `write_file` / `edit_file` / `exec` / `spawn` -> `executing`
6. 当最终文本开始输出时，办公室会切回 `writing`。

## 当前未完成

1. `pet mode` 还没有接入办公室场景。
2. 现在只有主 Agent 真正接入了状态同步，多 Agent 仍是结构预留。
3. 资产系统只有数据驱动雏形，还没有配置 UI、收藏、回滚、主题切换。
4. `thinking`、更细的工具分类、动作细分还没有补上。
5. 目前 `researching / executing` 主要来自 `Nanobot tool-hint`，不是完整的通用推理阶段协议。

## 下一阶段任务

### 任务 1：Pet Mode 办公室接入

目标：让桌宠模式也能看到简化版像素房间或房间状态缩略视图。

建议内容：
- 在 `front_end/src/shells/PetShell.jsx` 接入轻量版办公室组件。
- 控制尺寸、信息密度和鼠标交互，避免破坏现有 pet mode 体验。
- 明确桌宠模式下的展示策略：完整房间、迷你房间，或仅角色状态区。

### 任务 2：办公室状态模型继续细化

目标：让房间状态更贴近实际行为，而不是只区分少数几类。

建议内容：
- 增加 `thinking`。
- 细化 `researching` 与 `executing` 的工具分类。
- 为不同状态补充更合适的文案、动作和区域表现。
- 评估是否需要把 `tool-hint` 语义前移到 Python bridge，减少 JS 侧字符串推断。

### 任务 3：多 Agent Presence 设计与接入

目标：让未来多个 Agent 可以稳定映射到房间里。

建议内容：
- 定义统一的 `agent presence` 数据结构。
- 明确字段：`agentId`、`displayName`、`businessState`、`detail`、`role`、`updatedAt`。
- 决定多 Agent 的写入源头是在主进程统一维护，还是由特定 runtime 汇总后写入。
- 设计同一区域多 Agent 占位策略和优先级规则。

### 任务 4：房间配置与资产持久化

目标：让房间不再只是硬编码展示，而是可配置、可扩展。

建议内容：
- 把房间布局、区域、家具、层级继续收敛成稳定配置格式。
- 设计用户持久化数据：主题、背景、家具摆放、角色皮肤。
- 明确配置落盘位置和版本升级策略。

### 任务 5：资产系统 UI

目标：让用户可以真正定制房间，而不是只能改代码。

建议内容：
- 做房间主题切换面板。
- 做背景与家具选择器。
- 做收藏、恢复默认、回滚上一次配置。
- 后续再考虑拖拽摆件和更细的编辑器体验。

## 推荐优先级

1. `pet mode` 办公室接入
2. 状态模型细化
3. 多 Agent presence 设计与接入
4. 房间配置与资产持久化
5. 资产系统 UI

## 建议的阶段验收点

1. 先确认主界面办公室的视觉方向是否正确。
2. 再确认 `researching / executing / writing / syncing / error` 的切换是否符合直觉。
3. 之后再进入 `pet mode` 和多 Agent，不要同时并行推进全部后续目标。

## 备注

当前版本已经可以作为“像素办公室第一阶段”使用，但还不能算完整完成最初三期路线图。后续开发应以“先扩展示范面，再抽象协议，再做资产系统”为顺序，避免过早做大而失控。
