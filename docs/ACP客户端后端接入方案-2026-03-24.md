# ACP 客户端后端接入方案（2026-03-24）

状态：Draft  
作者：Codex（协同讨论稿）

## 1. 结论先行

本项目将 ACP 作为内部连接协议接入，而不是作为用户可见的后端类型。

目标形态：

- `Conversation Runtime` 继续对接统一后端事件。
- 新增 `claudeCodeBackend`、`codexBackend`，与 `nanobotBackend` 并列。
- `claudeCodeBackend/codexBackend` 内部复用 ACP client transport，把 ACP 事件翻译为项目内统一事件（text-delta / agent-state / done / error 等）。
- RBEP 继续作为内部统一语义层存在，不与 ACP 二选一。

用户可见命名原则：

- 前端展示：`nanobot`、`claude code`、`codex`。
- 不向用户展示：`ACP`、`stdio JSON-RPC`、`transport` 等协议术语。

## 2. 分层边界

```text
Conversation Runtime
  -> Chat Backend Adapter (nanobot | claude-code | codex | ...)
    -> (claude-code/codex backend 内部) ACP Client Transport
      -> External ACP Agent (Claude Code / Codex / other)
```

边界定义：

1. ACP 解决“如何连接外部 Agent”。
2. RBEP 解决“Runtime 如何稳定消费后端事件”。
3. Renderer 不直接消费 ACP 原生事件。

## 3. 与现有代码的对应关系

当前运行链路中，前端和 Runtime 只稳定依赖少量事件类型：

- `text-delta`
- `segment-ready`
- `done`
- `error`
- （可选）`agent-state`

因此 ACP 接入应通过适配器归一化，不应把 ACP 事件模型直接泄露到 Runtime/Renderer。

## 4. ACP -> 内部事件映射（Phase 1 最小可用）

| ACP 语义 | 内部事件类型 | 说明 |
|---|---|---|
| 会话开始/接受 | `stream-start` | 可由适配器合成 |
| 文本增量/消息块 | `text-delta` | `payload.content` 为增量文本 |
| 工具调用中 | `agent-state` | 映射为 `researching/executing` |
| 正常结束 | `done` | 可携带 `finishReason` |
| 异常结束 | `error` | 映射 `code/message/status` |
| 用量信息（若有） | `usage` | 可选，不影响主流程 |
| 产物（若有） | `artifact` | 可选，不影响主流程 |

注：Phase 1 先保证对话主链路稳定，不要求完整映射全部 ACP 扩展事件。

## 5. 用户可见后端与内部协议映射

| 用户看到的后端 | 内部实现 | 备注 |
|---|---|---|
| `nanobot` | `nanobotBackend` | 现有实现 |
| `claude code` | `claudeCodeBackend` + ACP client | 新增 |
| `codex` | `codexBackend` + ACP client | 新增 |

说明：

1. ACP 是新后端的内部实现细节，不单独作为后端选项出现。
2. 后续若新增其他 ACP 生态 Agent，也按“品牌后端 + 内部 ACP”模式接入。

## 6. Permission 策略（后端先就绪）

### 6.1 设计目标

虽然前端权限配置稍后再做，但后端需先具备策略位与处理路径，避免后续重构。

### 6.2 建议策略枚举

- `deny`（默认）：自动拒绝权限请求。
- `allow`：自动放行权限请求（仅开发/受控场景）。
- `ask`：预留模式，等待前端权限交互接入。

### 6.3 超时与安全默认

- `ask` 模式在前端未接入前，按超时拒绝处理。
- 默认策略必须是 `deny`。
- 所有权限决策需写入 debug 日志（不含敏感信息）。

## 7. 实施分期

### Phase 1：最小可用（推荐先落地）

1. 新增 `claudeCodeBackend` 与 `codexBackend`。
2. 新增共享 ACP 传输客户端（先支持 `stdio`）。
3. 完成最小事件映射（text-delta/done/error/agent-state）。
4. 实现 permission 策略位（deny/allow/ask），默认 deny。
5. 增加桌面主进程测试覆盖：终态唯一、abort、错误映射。
6. 前端后端选择器展示 `nanobot/claude code/codex`，不展示 `acp` 选项。

### Phase 2：能力完善

1. 支持 HTTP/WebSocket ACP 传输。
2. 完整映射 usage/artifact 等扩展事件。
3. 接入前端 permission UI（`ask` 模式闭环）。

### Phase 3：稳定性与可观测

1. 增加 conformance tests（协议一致性测试）。
2. 增加会话级指标：延迟、超时、permission 拒绝率。
3. 补充回归脚本（多后端切换与中断恢复）。

## 8. 配置建议（草案）

建议对外保留品牌化后端字段，对内保留协议配置。示例：

```json
{
  "chatBackend": "codex",
  "claudeCode": {
    "enabled": false,
    "runner": {
      "protocol": "acp",
      "transport": "stdio",
      "command": "claude-agent-acp",
      "args": []
    },
    "timeoutMs": 120000,
    "permissionMode": "deny"
  },
  "codex": {
    "enabled": false,
    "runner": {
      "protocol": "acp",
      "transport": "stdio",
      "command": "codex-acp",
      "args": []
    },
    "timeoutMs": 120000,
    "permissionMode": "deny"
  }
}
```

说明：

- `chatBackend` 是用户可见后端标识，不是协议标识。
- `runner.protocol=acp` 仅内部使用，不暴露为用户可选后端。
- `permissionMode` 是后端权限策略位。
- 前端暂未提供配置入口时，可先走默认值与开发开关。

## 9. 风险与缓解

1. ACP agent 事件差异大：
   - 缓解：保持“最小事件核心”，其余事件可选映射。
2. 权限请求未闭环：
   - 缓解：默认 deny + ask 超时拒绝。
3. 中断语义不一致：
   - 缓解：统一收敛到 `done{aborted:true}` 或 `error{code:"aborted"}`。

## 10. 验收标准（Phase 1）

1. 可切换到 `claude code` 或 `codex` 后端并完成一轮文本对话。
2. `latest-wins` 与 `abort` 语义与现有后端一致。
3. 发生异常时必有 `error` 终态，正常结束必有 `done` 终态。
4. permission 请求在无前端交互时按策略可预测处理（默认拒绝）。
5. 不破坏现有 `nanobot` 链路与 Renderer 消费逻辑。
6. 设置与 UI 中不出现“ACP 后端”字样，用户只看到品牌后端。

---

本方案是“协议内聚、品牌外显”的工程路线：内部用 ACP 打通能力，外部以具体引擎形态呈现给用户。
